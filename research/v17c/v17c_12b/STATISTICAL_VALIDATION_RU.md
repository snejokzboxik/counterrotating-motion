# V17C.12B — статистическая валидация

## Что проверено

Для однорадиусного Al₂O₃ Sobol-экрана выполнен аудит структуры данных: 4096 строк и 4096 уникальных ключей `(screen_index,start_index)`, ровно 8 стартов в каждой из 512 конфигураций, совпадение всех начальных состояний и фаз в JSONL с frozen NPZ, SHA runner совпадает с архивированной копией. Результат: `results/identical_physical_sobol_screen_corrected/independent_audit.json` (`integrity_pass=true`).

## Чего эти данные не оценивают

На конфигурацию приходится только 8 общих scrambled-Sobol rest-стартов. Параметры по разным конфигурациям различны, а бинарные метки предварительны и собраны после горизонта 5000 периодов. Поэтому 0 встречных случаев среди 4096 строк нельзя преобразовывать в биномиальную верхнюю границу вероятности: строки не являются IID выборкой из одной и той же системы. Для каждой конфигурации n=8 также недостаточно, чтобы заявить подавление редких `(++)/(−−)` или отсутствующий бассейн.

Доли `(++)`, `(−−)` и потерь в `BISTABILITY_ANALYSIS_RU.md` описывают только поисковую сетку. Они не равны вероятностям для наилучшей точки.

Многорадиусный экран добавил ещё 4096 строк, но восемь радиусов и их размерно связанные настройки — разные физические системы. Его нулевое число встречных меток является самостоятельным результатом поиска; объединять 8192 строки в одну статистику вероятностей нельзя.

Экспериментально привязанный экран 50 Hz добавил 6144 строки, включая 8 rest- и 8 reference-speed стартов на каждую из 384 фиксированных конфигураций. Он также является discovery-выборкой: starts по конфигурациям фиксированы и не IID, каждый короткий классификатор — не длинная аттракторная проверка. Знаменатели rest и injection нужно показывать отдельно; объединение их в одну вероятность не характеризует экспериментальную загрузку.

Отдельная directed-серия проверила 8 фиксированных 50-Hz конфигураций по 16 специально направленным стартам (8 каждой начальной ориентации), всего 128 траекторий длиной 15 000 периодов. Аудит подтвердил полное покрытие 8×16, уникальность ключей, совпадение starts/phases с замороженным NPZ, полные горизонты и SHA runner/integrator/field. Исходы: 64 предварительные `(++)`, 64 предварительные `(−−)`, 0 CR. Это отвечает только на вопрос о сохранении выбранных встречных стартов у данных конфигураций; directed-выборка не имеет вероятностного знаменателя.

Новая фиксированная гетеропара Al₂O₃/K1 проверена отдельно четырьмя замороженными ансамблями по 128 стартов (512 всего), каждый при одних и тех же физических параметрах, RK4/64 и 15 000 периодах. Сырые экранные частоты по ensemble: удержание 126/128, 127/128, 119/128, 113/128; встречные исходы 0 во всех. Нельзя объединять эти заранее различающиеся стартовые ансамбли в IID-вероятность. Аудит подтвердил записи, размерные формулы и code/data hashes; доли остаются скрининговыми, а не строгими доверительными интервалами.

## План независимой проверки кандидата

Только после обнаружения одного фиксированного набора параметров с обоими встречными исходами следует использовать независимые IID или несколько независимых рандомизированных Sobol-пакетов. Для каждого ансамбля отдельно наращивать N: 128, 256, 512, 1024 и при необходимости 2048–4096. Сохранять `(+−)`, `(−+)`, `(++)`, `(−−)`, пару удержанных/потерянных и остальные метки в исходном знаменателе. Для нуля однонаправленных событий сообщать точную одностороннюю биномиальную верхнюю границу только для IID-серии.

Финальная проверка должна включать rest, weak, wide, edge; отдельно сообщать физический ансамбль загрузки, если его параметры измерены. В начальных условиях для одинаковых частиц обеспечивать распределение, инвариантное к перестановке индексов; использовать общие RF-фазы и отдельную переставленную проверку.

Пока ни один кандидат не прошёл условие начала такой статистической проверки. Планы по A/B-диапазону не заменяют результат.
